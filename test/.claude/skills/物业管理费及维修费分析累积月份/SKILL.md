# 物业管理费及维修费分析（累积月份）

根据新华医院物业及维修明细账 Excel 累计文件（1月至当前月份的全部交易数据），
按运营成本分类汇总物业管理费，按科目名称和运营成本两级分类汇总维修费，
自动更新分析底稿中相关 sheet 的数据。

> **与单月版本的关键区别**：本技能使用的明细文件包含从1月到当前月份的**所有交易记录**（累计数据），
> 而非仅当月数据。汇总结果反映的是**年初至今的累计金额**，用于与上年同期累计数据进行同比对比分析。

## 输入

- **本年累计明细文件**：如 `2026年1-6月物业维修费.xlsx`（含1-6月全部交易，.xlsx 新格式或 .xls 旧格式）
- **上年同期累计明细文件**：如 `2025年1-6月物业维修费.xls`（含上年1-6月全部交易，.xls 旧格式）
- **分析底稿**：如 `6月分析底稿.xlsx`
- **物业及维修明细文件**（两个独立 Excel，每个包含1月至当前月的累计数据）

## 执行

```bash
python .claude/skills/物业管理费及维修费分析累积月份/scripts/property_analysis.py \
  <本年累计明细文件> <上年同期累计明细文件> <分析底稿> [--output OUTPUT] [--mode MODE]
```

**模式选项**:
- `--mode all`（默认）：同时更新物业管理费和维修费
- `--mode property`：仅更新物业管理费
- `--mode maintenance`：仅更新维修费

示例：
```bash
# 完整分析（1-6月累计 vs 上年同期累计）
python .claude/skills/物业管理费及维修费分析累积月份/scripts/property_analysis.py \
  2026年1-6月物业维修费.xlsx 2025年1-6月物业维修费.xls 6月分析底稿.xlsx

# 仅维修费
python .claude/skills/物业管理费及维修费分析累积月份/scripts/property_analysis.py \
  2026年1-6月物业维修费.xlsx 2025年1-6月物业维修费.xls 6月分析底稿.xlsx --mode maintenance
```

无 `--output` 参数时，输出文件自动命名为 `<原名>_updated_<MMDD>.xlsx`。

## 格式检测

脚本自动检测明细文件格式并适配不同的列布局（`detect_format()`）：

| 特征 | 2026 新格式 (.xlsx) | 2025 旧格式 (.xls) |
|------|-------------------|-------------------|
| header 关键词 | row 3 col 1 = "年" | row 2 col 1 = "科目代码" |
| 运营成本列 | col 7 (G) | col 12 (L) |
| 院区列 | col 8 (H) | col 9 (I) |
| 借方金额列 | col 11 (K) | col 13 (M) |
| 科目编码列 | col 4 (D) | col 1 (A) |
| 科目名称列 | col 5 (E) | col 2 (B) |
| 数据起始行 | row 5 | row 3 |
| 运营成本格式 | 纯文本，如 `保安管理服务费` | 带前缀，如 `运营成本:物业管理_保安管理服务费` |
| campus_prefix | 无 | `分院:` |
| campus_map | `{"杨浦院区": "杨浦", "奉贤院区": "奉贤"}` | `{"杨浦院区": "杨浦", "奉贤院区": "奉贤"}` |

2026 新格式通过 `exclude_keywords` 列表排除非物业管理行（维修维护、空调、电站等），"其他"行也被排除。
2025 旧格式通过前缀匹配 `运营成本:物业管理_` 识别物业管理行。

配置在 `references/category_mapping.json` 的 `format_detection` 段中定义（仅供参考，实际逻辑以代码为准）。

## 维修费分析

### 数据规则

维修费与物业管理费共用同一明细文件，通过科目编码识别维修费行：
- **2026新格式**：科目编码含 `0412`（如 `5001041201`、`5101041204`）
- **2025旧格式**：科目代码去点后含 `0412`（如 `5001.04.12.01`）

### 两级分类体系

#### 一级分类（→ 维修护费 sheet）

基于**科目名称**，按优先级匹配：

| 匹配关键词 | 分类标签 | 维修护费行 |
|-----------|---------|-----------|
| 设备日常维修 | 设备维修 | R5 |
| 网络信息系统运行与维护费 | 网络维修 | R4 |
| 房屋日常维修 | 房屋维修 | R7 |
| 其他 + 科目编码以04结尾 | 后勤维修 | R6 |

- **2026新格式**：科目名称如 `设备日常维修（护）费`、`网络信息系统运行与维护费`、`房屋日常维修（护）费`、`其他`
- **2025旧格式**：科目名称如 `业务活动费用_商品和服务费用_维修（护）费_设备日常维修（护）费`

### 更新范围

#### 维修护费 sheet

仅更新**硬编码数值单元格**（行 4-7 的 C/D/E 列），保留所有公式：
- C 列：本年累计合计（万元，1月至当前月）
- D 列：奉贤累计（万元）
- E 列：上年同期累计（万元）
- F/G 列：增减额/增减率（公式，自动重算）
- R3（维修费合计）：公式 `=商品服务!C6`
- R5 柯渡数据（H5/I5/J5）：不更新，保留原值

#### 后勤维修 sheet

仅更新**硬编码数值单元格**，保留所有公式：

- **左表 (C-J列)**：
  - 更新 R6-R15 中 D/E/F 列数值（本年累计合计/奉贤累计/上年同期累计）
  - 保留 G/H 列公式
  - 保留 R5 公式（`=维修护费!C6`）
  - 保留 R16 公式（`=D5-D6-D7-...-D15`，其他）

- **右表 (K-P列)**：
  - 更新 R6-R8 中 L/M/N 列数值
  - 保留 O/P 列公式
  - 保留 R9 公式（`=L5-L6-L7-L8`，其他）

#### 商品服务 sheet R6

更新维修费汇总行（累计数据）：
- C6 ← 本年累计维修费总计（万元）
- D6 ← 本年累计奉贤院区维修费合计（万元）
- E6 ← 上年同期累计维修费总计（万元）

### 排除的科目

非维修费科目（科目编码不含 `0412`）的"其他"科目名称行不会被纳入维修费分析。
物业管理费行（科目编码含 `0409`）由物业管理费分析模块独立处理。

## 验证

运行后检查输出摘要：

### 物业管理费
- 每个分类的本年累计汇总金额（元）和院区分布
- 物业管理费累计合计金额（万元）
- `updated_cells`：成功更新的单元格数

### 维修费
- 一级分类（设备/网络/房屋/后勤维修）的本年累计汇总金额和院区分布
- 二级分类（后勤维修 10 个子项）的本年累计汇总金额和院区分布
- **交叉验证**：后勤维修子项之和 = 一级后勤维修值（预期完全相等）
- 维修费累计合计（万元）

### 交叉验证
- 左表子项之和 ≈ R5 物业管理费汇总
- 奉贤累计子项之和 ≈ 奉贤物业管理费
- 后勤维修子项之和 = 维修护费 R6 后勤维修值
- F/G/O/P 列公式保留且数值正确
- 本年累计数据应 >= 任一单月数据（数据一致性检查）

## 与现有技能的关系

本 skill 是**单月版本**（`物业管理费及维修费分析`）的累计数据变体。
两者的核心差异在于输入数据的范围：
- **单月版本**：处理当月明细文件 → 写入当月数据到分析底稿
- **本累积版本**：处理1月至当前月累计明细文件 → 写入累计数据到分析底稿

建议工作流：
1. 运行本 skill → 更新分析底稿中「物业管理」「维修护费」「后勤维修」「商品服务」sheet 的累计数据
2. 运行 **成本分析累积月份** skill → 从分析底稿的累计数更新 PPT

> 注意：如果分析底稿需要同时支持单月数据和累计数据，请确保两次运行使用不同的底稿副本，
> 或底稿中有独立的 sheet/列来区分单月值和累计值。

## 扩展

### 物业管理费
如需增加新的分类或调整映射：
1. 编辑 `references/category_mapping.json` 的 `categories` 数组
2. 添加 `keywords` 和 `label`
3. 指定 `left_row`（左表行号）和/或 `right_row`（右表行号）
4. 如需排除新的非物业管理分类，添加到 `exclude_keywords`

### 维修费
如需调整维修费分类：
1. 编辑 `references/category_mapping.json` 的 `maintenance` 段
2. 调整 `top_level.categories` 或 `logistics_repair.left_block.sub_categories`
3. 添加新的 keywords/label/data_key 组合
4. 重新运行脚本测试

### 格式检测
如需调整格式检测逻辑：
1. 编辑 `property_analysis.py` 的 `detect_format()` 函数
2. 调整列索引、起始行、前缀、campus_map 等
3. `references/category_mapping.json` 中的 `format_detection` 段仅供参考，以代码为准
